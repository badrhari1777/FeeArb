- Core layers: pipeline (data), orchestrator (decisions), execution (orders/positions), webapp (FastAPI + WS UI).

Dry Run Logic (ManualTradeManager in `execution/manual.py`)
- Dry run is a "plan-only" path; it builds a full execution plan and returns diagnostics, but never places orders.
- Entry point: `_handle_pair(...)`:
  - Calls `_build_plan(...)`.
  - If `payload.dry_run` or `plan.errors`, returns the plan immediately.
  - Otherwise executes the plan via `_execute_plan(...)` (or smart/fast enter/exit).
- `_build_plan(...)` does the heavy lifting:
  - Validates action, symbol, exchanges, qty/notional; can infer qty from positions for exit/roll.
  - Resolves qty from notional via ticker if needed.
  - For each leg:
    - Ensures exchange client (requires credentials unless ccxt supports public-only for that exchange).
    - Resolves ccxt symbol.
    - Fetches orderbook: prefers websocket (`orderbook_provider.get_orderbook`), else REST.
    - Extracts market constraints (min qty, min notional, amount step, contract size).
    - Applies optional min-notional overrides and buffer.
    - Scales orderbook for contract size, computes stats and liquidity.
    - Estimates fill, slippage, and max qty under slippage limit.
    - Adds errors if insufficient liquidity when `use_orderbook_check` is true.
  - Calculates funding meta, spread %, recommended qty/notional, and chunk sizing hints.
  - Optionally collects constraints for multiple exchanges if `constraints_exchanges` is provided.
  - Returns plan payload with `errors`, `warnings`, `stats`, `slippage`, `market_constraints`, etc.
- Key outcome: dry run is a comprehensive preflight check + sizing advisor, not a simulation of execution steps.

Notes / Observations on Dry Run

Gate WS Notes (Futures v4)
- Two signature modes:
  - Private subscriptions use `auth` with signature `channel=<channel>&event=<event>&time=<time>`.
  - Trading requests use `event: "api"` with signature `api\n<channel>\n<req_param>\n<timestamp>`.
- Must send `futures.login` (`event: api`) before `futures.order_place`/`futures.order_cancel`.
  - Login payload includes `api_key`, `signature`, `timestamp`, `req_id`, `request_param: ""`, `headers: {}`.
  - Use server time offset (`time_ms` or `header.response_time`) and retry once on timestamp errors.
- Subscriptions need a contract param: payload `[<contract>]` or `[<uid>, <contract>]`; use `!all` for all contracts.
- Validated flow: login -> subscribe (`orders`/`positions`/`usertrades`) -> order place/cancel -> WS updates (open/filled/canceled) + positions/usertrades.

Kucoin WS Notes (Classic Futures)
- Private token via `/api/v1/bullet-private`, then connect to returned `endpoint?token=...`.
- Orders stream: `/contractMarket/tradeOrders` (optionally `:SYMBOL`).
- Positions stream: `/contract/positionAll` or `/contract/position:SYMBOL`.
- Wallet stream: `/contractAccount/wallet`.
- Validation: REST limit orders (manual tests) trigger `symbolOrderChange` updates on `/contractMarket/tradeOrders:SYMBOL` (open -> match -> filled), plus wallet updates and `/contract/position:SYMBOL` position changes. Order events carry `marginMode: ISOLATED` and `positionSide: BOTH`.
- Classic docs do not list `tradeFills`; use order updates or REST for fills.

Backend also gained CSV export helpers/routes for review payloads: `GET /api/coin/review/weekly.csv` and `GET /api/coin/review/{symbol}/timeline.csv`, flattening trade-activity + shortlist rows into a ChatGPT/Excel-friendly timeline (`webapp/templates/coin.html`, `webapp/static/coin.js`, `webapp/services.py`, `webapp/app.py`, `tests/test_coin_export.py`).
- Weekly review now has first operator heuristics instead of only raw history. `get_coin_weekly_review(...)` builds `review_tags` with simple transparent rules: `missed_entry` (strong shortlist row without nearby trade), `late_exit` (stored outcome says exiting 15m earlier would have helped and alternative delta is materially negative), and `stale_position` (open paper position older than 24h with no follow-up actions after entry). These tags are exposed in JSON/CSV review exports and rendered in `/coin` as a dedicated `Review tags` table plus summary counts (`webapp/services.py`, `webapp/templates/coin.html`, `webapp/static/coin.js`, `tests/test_coin_export.py`).
- Weekly review tags are now prioritized, not just listed. Each `review_tag` gets an `impact_score` and severity (`info/warn/high`) so the operator can sort weekly issues by likely cost/importance: `missed_entry` scores from shortlist strength + rank + edge, `late_exit` from counterfactual net delta and poor timing, and `stale_position` from idle age. Review summary now exposes `review_tag_severity_counts` and `top_review_items`, and the `/coin` UI shows score directly in the `Review tags` table plus compact “top review items” in the summary block (`webapp/services.py`, `webapp/templates/coin.html`, `webapp/static/coin.js`, `tests/test_coin_export.py`).
- Weekly review is now split into structured `entry review` and `exit review` slices in addition to the global tag list. Backend groups tags into `entry_review.tags` (`missed_entry`) and `exit_review.tags` (`late_exit`, `stale_position`), each with its own `summary.total`, per-tag counts, and `top_items`. `/coin` now renders dedicated `Entry review` and `Exit review` tables so the operator can review entry mistakes and exit mistakes separately instead of scanning the mixed tag feed. Missed-entry detection was also refined to suppress false positives when a trade happened near the shortlist timestamp on either side, not only after it (`webapp/services.py`, `webapp/templates/coin.html`, `webapp/static/coin.js`, `tests/test_coin_export.py`).
- `Entry review` now covers not only missed opportunities but also bad and correctly skipped entries. New tags in `get_coin_weekly_review(...)`: `bad_entry` for entry actions (`ENTRY_SMALL/ENTRY_STRONG/ADD_SMALL`) that later underperformed or were outright incorrect, and `good_no_trade` for `NO_TRADE/ADD_BLOCKED` decisions that correctly avoided a losing entry. These are included in `entry_review.tag_counts`, global `review_tags`, and CSV/JSON exports, with the same `impact_score/severity` prioritization as other weekly-review heuristics (`webapp/services.py`, `tests/test_coin_export.py`).
- `Exit review` now also tracks positive and negative hold/exit quality, not only late/stale cases. Added `good_exit` for `PARTIAL_EXIT/FULL_EXIT` decisions whose stored outcomes confirm exiting was the better choice versus waiting, and `bad_hold` for `HOLD` decisions that clearly underperformed even when they do not fit the narrower `late_exit` condition. These are included in `exit_review.tag_counts`, `exit_review.tags`, and export payloads with the same impact/severity ranking as the rest of weekly review (`webapp/services.py`, `tests/test_coin_export.py`).
- `Auto Exit V1 Diagnostics` now runs in shadow mode for ordinary active auto-exit rules even when the per-row `v1` toggle is off. The scheduler in `webapp/services.py` now computes the same `v1` hold/exit decision payload for spread-enabled rules and appends it to `auto_exit.v1_diagnostics` with `status=shadow` (or `skip` when context is unavailable), while actual `v1` execution still requires `v1_enabled=true`. The dashboard hint text was updated accordingly and regression coverage was added to ensure shadow diagnostics populate without calling `manual_exit(...)` (`webapp/services.py`, `webapp/templates/index.html`, `webapp/static/app.js`, `tests/test_project_settings.py`).
- `Auto Exit V1` take-profit was tightened to avoid early exits on weak funding edge. The TP threshold in `webapp/services.py` is now `max(40 bps, 4 x funding_to_next_bps)` instead of the older lower floor / window-varying multiplier, so examples like `funding_to_next=+0.05%` with `close_now=+0.30%` stay in `hold` because they do not clear the new `0.40%` minimum. Window payloads now report `TP K = 4.0x` consistently, and regression coverage was added for both the `40 bps` floor and the `4x funding` branch (`webapp/services.py`, `tests/test_auto_exit_multileg.py`).
- Manual-trade `Expensive leg (manual) = Auto hint` now resolves consistently during execution, not only in dry-run output. `execution/manual.py` now uses one shared primary-leg resolver across `limit-first-expensive`, `smart-enter`, `smart-exit`, `smart-roll`, and fast enter/exit ordering, so the plan’s `suggested_expensive_leg` (tier -> fee -> liquidity -> tie-break) is applied whenever no explicit override is chosen. Roll suggestions are also mapped correctly from `long/short` into `to/from`. Added regression coverage for auto-hint leg resolution and `limit-first-expensive` / `smart-enter` execution paths (`execution/manual.py`, `tests/test_manual_trader.py`).
