# Правила ручной live-торговли FeeArb

Область действия: ручные `Enter`, `Exit` и `Roll` в `execution/manual.py`.

## Основной источник состояния

- Приватные WebSocket-потоки являются основным источником данных об исполнении ордеров.
- Заполненное количество отслеживается по `order_id`.
- Состояние WS определяется heartbeat и трафиком соединения, а не только событиями ордеров.
- Перед переходом на REST выполняются проверка heartbeat и попытка переподключения.
- REST-статус ордера используется как fallback только для конкретного `order_id`.

## Позиции

- Начальный снимок позиций берется перед выполнением.
- Финальный снимок используется для reconciliation.
- Если дисбаланс не меньше допустимого fallback minimum, выполняется рыночное выравнивание.

## Smart/Limit

- Один chunk исполняется полностью до перехода к следующему.
- Сначала исполняется primary leg, затем hedge leg.
- Указанный вручную chunk является целевым максимумом, но всегда уменьшается до
  допустимого объема ликвидности при заданном `max slippage`.
- Тонкие уровни стакана ниже минимального порога игнорируются.
- Собственный активный ордер исключается из проверки лучшего уровня.
- При repricing новый ордер размещается только после подтверждения отмены старого.
- Margin mode и leverage устанавливаются один раз на сделку, а не перед каждым
  chunk.

## Spread и время исполнения

- В Manual задается одна граница spread:
  - `Enter`: запуск при `текущий spread <= цель`.
  - `Exit`: запуск при `текущий spread >= цель`.
  - `Roll`: оператор явно выбирает `<=` или `>=`.
- Desktop Manual, мобильная web-страница и Android используют одинаковую
  семантику. В API она по-прежнему передается совместимыми полями
  `spread_max_pct` для `<=` и `spread_min_pct` для `>=`.
- Если до первой заявки условие spread не наступило за `Trigger wait`
  (по умолчанию 30 секунд), процесс освобождает общий worker без сделок.
- `Max runtime` ограничен 600 секундами; базовое значение Manual — 180 секунд.
- Для auto-exit базовый runtime остается 120 секунд.
- Обычный Stop прекращает создание новых primary-ордеров, отменяет текущий primary-ордер и затем обязательно хеджирует его финальный fill. Исполнение не должно завершаться с новым перекосом только потому, что primary-ордер исполнился во время отмены.

## Fast/Market

- Рыночные chunks отправляются одновременно на обе ноги.
- После каждого chunk система ждет восстановления ликвидности стакана.
- При таймауте chunk может быть уменьшен до доступной ликвидности.
- Выполнение останавливается, если доступное количество ниже биржевого минимума.

Текущие базовые значения:

```text
market_fill_timeout_sec = 3
market_refill_bps = 10
market_refill_buffer = 0.15
market_refill_max_wait_sec = 5
hedge adverse move threshold = 0.1%
```

## REST и WebSocket

- Размещение и отмена ордеров: ccxt REST.
- Fill и статус ордера: приватные WS order/trade updates.
- Позиции: WS для начального и финального снимка.
- REST positions допускается только при устаревшем или недоступном WS после попытки reconnect.

## Операторская безопасность

- Всегда выполняйте `Dry Run`/`Analyze` перед live-submit.
- Проверяйте symbol, обе биржи, side, qty/notional, chunk и max slippage.
- Короткие symbols сопоставляются точно: например, `H` не включает `HOME`.
- `Execute` может отправить реальные ордера.
- При `Exit` и `Roll` отдельно проверяйте остаток позиции и допустимость переворота ноги.
- Основные поля находятся в верхней строке Manual. Настройки исполнения,
  хеджа и отдельные WS-настройки бирж находятся в раскрывающихся блоках.
## Размер чанка и проскальзывание

- Для ручного входа стандартный `Max slippage` равен `12 bps`; чанк всё равно ограничивается текущей ликвидностью обеих ног.
- Для сокращения позиции через кнопку `Exit` сохраняется более консервативный предел `8 bps`.
- В execution-логе событие `smart-enter chunk` / `smart-exit chunk` показывает `max_qty_by_exchange`, `limiting_exchange` и фактический предел `max_slippage_bps`.
