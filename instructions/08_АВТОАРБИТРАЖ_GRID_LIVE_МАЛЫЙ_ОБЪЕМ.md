# Автоарбитраж Grid: Live

Основной адрес:

```text
https://desktop-0tl9bsa.tail3830e2.ts.net:8443/auto-arbitrage
```

Публичный адрес:

```text
https://app.feearb.ru/auto-arbitrage
```

Публичный адрес используйте только после проверки HTTP `200`. Tailscale остается
основным операционным маршрутом.

## Расчет сетки

1. Задаются символ, long/short биржи, максимальный объем в монетах или USDT,
   первый и последний entry spread.
2. Dry Run выполняется отдельно для входа и выхода.
3. Если число уровней не задано, оно рассчитывается из меньшего безопасного
   размера входного/выходного чанка с коэффициентом ликвидности `0.70`.
4. Grid-ступень является целевым изменением позиции. Она не является размером
   одного биржевого ордера.
5. При Live-исполнении `smart-enter` / `smart-exit` заново оценивает стаканы и
   может выполнить одну ступень несколькими динамическими чанками.
6. `Exit gap` рассчитывается автоматически как арифметический шаг сетки:
   `abs(первый вход - последний вход) / (число уровней - 1)`.
   Поэтому выход заполненной ступени совпадает с entry-уровнем предыдущей
   ступени. Ручная настройка gap не используется.

Старые серверные ограничения `50 USDT` на чанк и `100 USDT` на позицию сняты.
Ограничителем остается бюджет стратегии, баланс, market constraints, глубина
стакана и заданный slippage.

## Принятие существующей позиции

При включении Live сервер обновляет позиции обеих бирж и сопоставляет
`hedged_qty = min(long_qty, short_qty)` с накопленным объемом уровней.

- позиция около объема уровня принимается как уже заполненная;
- допускается отклонение до `1%` размера одной ступени;
- небольшой перекос ног в пределах того же допуска считается dust;
- сохраняются `adopted_level`, `adopted_qty` и время принятия;
- исторический spread ручного входа автоматически не восстанавливается:
  уровень определяется фактическим количеством монет.

Если объем не соответствует ни одному уровню или перекос существенный, Live
активация блокируется.

## Исполнение ступени

1. Grid наблюдает entry/exit spread вне execution worker.
2. После нужного количества подтверждений он пытается занять общий worker.
3. Исполнитель работает только с одной текущей ступенью.
4. Нехватка ликвидности на полный объем ступени не отменяет запуск. Preflight
   записывает предупреждение, а `smart-enter` / `smart-exit` уменьшает текущий
   чанк до доступного `max_qty` в пределах заданного slippage.
5. Одна ступень может быть исполнена несколькими подчанками. После каждого
   запуска позиции сверяются с биржами.
6. Полное исполнение переводит Grid на следующий уровень.
7. Парное частичное исполнение сохраняется как `pending_transition`. У такой
   ступени одновременно контролируются два порога, но решение принимает один
   арбитр и запускается только одна операция:
   - частичный `enter`: по entry-порогу докупается только остаток ступени, по
     exit-порогу продается уже исполненная часть;
   - частичный `exit`: по exit-порогу продается только старый остаток ступени,
     по entry-порогу выкупается назад уже проданная часть;
   - между entry- и exit-порогами позиция не меняется.
8. Если обратная операция сама исполнилась частично и спред снова развернулся,
   целевой объем восстанавливается до исходной границы ступени. Например, после
   продажи `600` из `1000` и обратной покупки `100` возврат exit-порога требует
   продать `500`: старый остаток `400` плюс обратную покупку `100`.
9. Перед каждым повторным или обратным запуском Grid обновляет обе биржевые
   позиции и пересчитывает объем от фактического `hedged_qty`. Для принятой
   через Adopt Grid позиции сохраняется ее реальный исходный объем, а не
   подставляется номинальный объем таблицы уровней.
10. Для обоих направлений действуют обычные `confirm_samples`; смена сигнала до
    первого исполнения отменяет подготовленную обратную операцию и возвращает
    исходный переход без лишней сделки.
11. Остаток до `1%` ступени считается `completed_with_dust`.
12. Существенный перекос запускает reduce-only hedge repair лишней ноги.
13. Если после штатного hedge repair обе биржи подтверждают нулевую позицию,
    Grid сбрасывает `live_level` в `0`, очищает старый `pending_transition` и
    возвращается в `waiting_entry`. Старый остаток ступени после полного
    закрытия повторно не исполняется.
14. Ошибки минимального шага или минимального объема переводятся в
    `completed_with_dust` только если часть Grid-операции уже реально
    исполнилась и других ошибок нет. Ошибки связи, баланса, позиции и
    выставления ордера остаются блокирующими.
15. Следующие уровни не рассматриваются, пока текущая ступень не завершена.

В веб-интерфейсе и мобильном списке Grid для частичной ступени показываются оба
действующих порога и объемы `BUY`/`SELL` для текущего состояния.

Недостаточный баланс для минимального биржевого объема остается блокирующей
ошибкой: Grid не должен создавать первую ногу, если вторую нельзя обеспечить.

## Общий worker и приоритет

В одном цикле Auto Agent проверяет:

1. emergency de-risk / orphan;
2. Spread и V1 Auto Exit;
3. лестничные Auto Exit / Auto Enter;
4. Grid.

Реальное исполнение одновременно только одно. Первый успешно запущенный
механизм занимает worker. Ручной Execute использует тот же slot и получает
`execution_busy`, если он уже занят. Ожидание Grid-триггера worker не занимает.

## Risk limit KuCoin до первого ордера

Для Classic Futures в isolated margin Grid читает выбранный KuCoin risk-limit
level и публичную таблицу уровней до включения Live. Проверяется не только
текущая позиция, а максимальный целевой объем всей сетки по свежей mark price с
запасом `1%`. Если выбранный уровень не покрывает этот объем, Live-активация
блокируется до выставления первого ордера и показывает требуемый уровень.

Та же проверка повторяется перед каждым `enter`-переходом. Изменение цены или
биржевой таблицы risk limit поэтому не может привести к сценарию, где первая
нога исполнилась, а KuCoin-хедж отклонен с `300005 maximum risk limit`.

KuCoin позволяет менять isolated risk-limit level приватным API
`POST /api/v1/position/risk-limit-level/change`. Backend умеет определить, что
этот endpoint доступен, но не вызывает его автоматически: KuCoin отменяет все
открытые ордера при изменении уровня. На существующей позиции сначала нужен
операторский план восстановления защитных TP/SL, затем отдельное подтвержденное
изменение уровня и полная повторная проверка защиты.

Команда Pause не запускает новый переход после начала паузы. Если execution уже
успел завершиться, его позиции все равно сверяются у выключенного правила;
существенный перекос закрывается reduce-only repair, а сбалансированное правило
остается в `paused` без повторного входа.

## Ограничения

- можно держать несколько Live Grid, но исполняются они последовательно;
- за один переход обрабатывается одна ступень;
- matching Auto Exit для той же пары должен быть выключен;
- один символ не может одновременно принадлежать двум Live Grid, если они используют хотя бы одну общую биржу; это относится и к `Adopt full grid`. Перед созданием новой Live Grid старую нужно поставить на паузу или удалить. Backend проверяет конфликт при сохранении, при Live-активации и перед каждым исполнением; найденные старые дубли блокируются без размещения ордеров;
- изменение диапазона активной Live-сетки пока запрещено;
- неизвестный результат заявки, неверная сторона позиции или невозможность
  безопасно восстановить хедж остаются причинами защитной остановки;
- Shadow сохранен только для совместимости старых правил, новые правила
  запускаются сразу в Live.

## Перед запуском

Проверьте API-ключи, баланс, isolated margin, плечо 3x, направление ног,
минимальный размер ордера, таблицу уровней и Dry Run обеих сторон. Для KuCoin
также убедитесь, что Grid risk-limit preflight имеет `ready=true`; вручную
поднимать уровень без учета отмены открытых ордеров нельзя.
