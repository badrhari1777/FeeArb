# FeeArb: реестр модулей и план безопасного рефакторинга

## Статус и цель

Этот документ является каноническим реестром production-модулей FeeArb на
период большого рефакторинга 2026-08. После каждого смыслового блока нужно
обновлять фактический статус, перенесенные уроки, тесты и следующий шаг.

Рефакторинг не является разрешением на изменение live-позиций. Перезапуск
backend и повторный `ARM PUMP LIVE 3000` остаются отдельными операторскими
действиями. Strategy Lab остается `research_only_no_trading`.

## Решения оператора

- сохранить Auto-Arbitrage Grid;
- удалить недоделанный Auto Strategy;
- вывести Auto Exit из runtime до полной замены на исследованный lifecycle;
- вывести из runtime любое автоматическое сокращение позиций и старую политику
  emergency de-risk;
- сохранить защитные стопы, контроль изолированной маржи, автоматическое
  добавление маржи, проверку свежести биржевых позиций и безопасный технический
  reduce-only executor без самостоятельного решения о сокращении;
- сохранить Manual Trade, ручной Spread Monitor и ручную Funding History;
- убрать старый Coin Analysis и старый candidate discovery из production;
- сохранить Pump Live, его signal feeder, управление капиталом и переводы;
- развивать Strategy Lab как единый источник будущих проверяемых гипотез;
- перед удалением любого старого кода сохранить его полезные алгоритмы, ошибки
  и обязательные regression cases в этом документе.

## Авторитетная runtime-граница

Production ownership зафиксирован в `webapp/runtime_modules.py`. Эти флаги не
являются пользовательскими настройками и не могут быть включены старым JSON или
формой браузера.

Активные контуры:

- account monitor и биржевые позиции;
- positions-market cache;
- protective orders и margin add;
- Manual Trade;
- Auto-Arbitrage Grid;
- Pump Live;
- Strategy Lab Observatory.

Выведенные из recurring runtime:

- Auto Exit;
- Auto Strategy;
- position-reduction/de-risk decision loop;
- legacy Coin Analysis;
- legacy candidate discovery.

## Реестр модулей

### Account Monitor, balances и positions

Статус: `KEEP_ACTIVE`.

Сохранить:

- exchange-authoritative позиции и балансы;
- явные freshness/status/error поля;
- нормализацию coin quantity и текущего USDT notional;
- отдельные Main и Pump account aliases;
- bounded polling только нужных бирж.

Доработать: выделить единый read-model и убрать повторные приватные запросы из
Manual, protection, Grid и web views.

### Manual Trade и общий execution kernel

Статус: `KEEP_ACTIVE_REFACTOR`.

Сохранить:

- независимые caps по qty и USDT notional с выбором меньшего объема;
- maker-first primary leg и немедленное хеджирование фактического fill;
- partial fill, cancel-confirm, retry, dust reconciliation;
- exchange constraints, contract multiplier и risk-limit preflight;
- WS-first order/position confirmation с REST fallback;
- dry-run как plan-only preflight.

Доработать: разделить planning, exchange gateway, execution state machine,
reconciliation и audit. Ручной exit/roll остается операторским действием.

### Protective orders и margin control

Статус: `KEEP_ACTIVE_SAFETY_CRITICAL`.

Сохранить:

- isolated margin и целевое плечо;
- stop/take classification разных бирж;
- gap-free replacement, Full-position semantics и close-all validation;
- margin add при ухудшении liquidation buffer;
- свежую повторную проверку после каждого изменения;
- fail-closed поведение при неизвестном состоянии биржи.

Не включать до отдельного исследования:

- auto margin reduce;
- auto rebalance;
- выбор позиции для сокращения;
- автоматическое закрытие прибыльной или убыточной позиции.

### Auto-Arbitrage Grid

Статус: `KEEP_ACTIVE_PRODUCT`.

Сохранить:

- ступенчатую state machine по фактической, а не номинальной позиции;
- симметричные partial-enter/partial-exit reversals;
- hedge repair и возможность выхода при заблокированном новом входе;
- adoption существующей позиции;
- ownership conflict и KuCoin risk-limit preflight;
- dust terminal state и exchange-authoritative reconciliation.

Будущее: Grid должен использовать общий execution kernel, но сохранять свою
отдельную стратегию и состояние.

### Auto Strategy

Статус: `REMOVE`.

Причина: недоделанный универсальный конструктор статических шагов не имеет
активных стратегий и будет заменен versioned proposals Strategy Lab.

Сохранить как regression knowledge:

- приоритет exit над enter;
- один общий execution worker;
- reconcile фактического прогресса шага;
- completion tolerance и защита от повторного выполнения.

### Auto Exit

Статус: `DISABLE_THEN_ARCHIVE`.

Причина: статическая формула не является доказанным lifecycle. Активных правил
на момент решения нет.

Сохранить для будущего `Lifecycle Executor`:

- executable bid/ask spread после fees;
- несколько подтверждающих циклов;
- position signature и verified missing-position logic;
- partial exit continuation и rule generation;
- venue liquidity tiers, aggressive-limit hedge и dust cleanup;
- строгую привязку результата к фактическому execution id.

Будущие решения `HOLD / PARTIAL_EXIT / EXIT / ROLL` должен выдавать отдельный
Strategy Lab policy package после chronological OOS, paper и shadow.

### Emergency de-risk и сокращение позиций

Статус: `DISABLE_DECISION_LOGIC`.

Старый score нельзя использовать для live-сокращений. Нужно сохранить только
безопасные примитивы: freshness veto, cluster ownership, orphan diagnostics,
reduce-only execution, max-action cap и reconciliation.

Новая политика должна исследовать funding, прогноз spread, liquidation buffer,
стоимость ожидания, доступный transfer и последствия выбора donor/loser/winner.
До ее promotion система не принимает самостоятельных решений о сокращении.

### Legacy Coin Analysis

Статус: `DISABLE_RUNTIME_ARCHIVE_DATA`.

Старая SQLite база не удаляется и не переписывается. После остановки writers ее
нужно подключать только read-only как исторический источник Strategy Lab.

Сохранить:

- held-position/manual-pin priority;
- funding interval normalization;
- feature/outcome identity и причинные horizons;
- data-quality veto вместо нулевых значений;
- position observation и operator decision journal.

Не переносить как торговое правило старые hand-written score thresholds.

### Legacy candidate discovery

Статус: `RETIRED`.

Главный dashboard больше не запускает старые Coinglass/ArbitrageScanner
collectors. Внешние источники принадлежат Candidate Observatory, служат seed и
обязательно проверяются собственным пятибиржевым feed.

### Pump Live

Статус: `KEEP_ACTIVE_SAFETY_CRITICAL`.

До закрытия live-позиций запрещен функциональный rewrite состояния. Дальнейшее
разделение допускается только с совместимой state migration и replay тестами.

Сохранить раздельные компоненты: signal admission, ladder state, isolated
margin, shared capital pool, transfers, protection, accounting, notifications
и restart recovery. Текущий Pump shadow schedule фактически является live
signal feeder для `main_pullback_tier`; его нельзя отключать без замены.

### Strategy Lab

Статус: `KEEP_ACTIVE_RESEARCH_ONLY`.

Strategy Lab формирует только versioned observations/features/proposals и не
имеет execution API. Текущий funding forecast остается research hold; простое
правило большого spread отклонено. Любая стратегия проходит
`historical -> chronological OOS -> unseen symbols -> paper -> shadow ->
operator-approved live`.

### Web, Android и diagnostics

Статус: `KEEP_SIMPLIFY`.

Главная страница должна показывать сначала общий капитал, биржевые счета,
Main/Pump позиции, protection/freshness и действующие модули. Редкие настройки
размещаются в нижнем закрытом `details`. Manual tests/raw WS остаются отдельной
operator/debug поверхностью и не должны загружать главную страницу.

## Безопасная последовательность

1. Отключить recurring workers retired-модулей неизменяемыми runtime flags.
2. Упростить главную страницу и убрать retired controls/routes из навигации.
3. Перенести тесты полезных state-machine свойств в будущие общие компоненты.
4. Удалить Auto Strategy production code.
5. Остановить Coin Analysis writers и сохранить SQLite read-only.
6. Разделить `DataService` на account/protection/manual/grid/read-model services.
7. Унифицировать exchange gateway/cache и измерить API load до/после.
8. Отдельно рефакторить Pump с совместимой state migration.
9. Удалять архивный код только после периода нулевых runtime/import обращений.
